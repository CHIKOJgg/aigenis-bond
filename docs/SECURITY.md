# Security Guide — Bonds Engine v4

## Authentication & Authorization

### JWT Tokens

- Algorithm: HS256
- Access token lifetime: 30 minutes (configurable via `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`)
- Refresh token lifetime: 7 days (configurable via `JWT_REFRESH_TOKEN_EXPIRE_DAYS`)
- Secret key: minimum 64 hex characters (generated by `scripts/generate_secrets.py`)

### User Roles

| Role | Permissions |
|---|---|
| `user` | Basic access: watchlist, portfolio, recommendations |
| `premium` | + ML predictions, advanced analytics, higher rate limits |
| `enterprise` | + API access, partner features, priority support |
| `admin` | + User management, tier changes, system config |

### OAuth (Google)

Optional Google OAuth is supported via `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.

## Webhook Security

### Telegram Webhooks

- **Secret token**: Validated via `X-Telegram-Bot-Api-Secret-Token` header
- The token is set when configuring the webhook with Telegram Bot API
- Requests without the matching header are rejected with 403

### Partner Webhooks

- **HMAC signature**: Each webhook payload is signed with the partner's secret
- **Secret delivery**: The secret is returned once at webhook creation and never stored in plaintext
- **Signature verification**: `HMAC-SHA256(secret, raw_body)` compared against `X-Signature` header

### YooKassa Webhooks

- **IP filtering**: Only YooKassa IP ranges are allowed (configurable via `YOOKASSA_WEBHOOK_IPS`)
- **API re-verification**: Every event is re-verified via the YooKassa API before processing
- **Refund protection**: Refunds only process if the full amount matches; cross-channel protection prevents duplicate refunds

## SSRF Protection

Webhook URL validation includes:
1. **DNS resolution pinning**: Hostname is resolved at registration time and the IP is stored
2. **IP allowlist**: Only pinned IPs are allowed to be contacted
3. **IPv6 support**: Full IPv6 address validation and pinning
4. **DNS rebind defense**: Resolution happens once; subsequent requests are validated against the pinned IP

## Admin Security

- **XFF spoofing protection**: The API trusts `X-Forwarded-For` headers only when `TRUSTED_PROXY=1` is set (i.e., behind a known reverse proxy)
- **Rate limiting**: Per-IP rate limiting on auth endpoints (10 req/s) and API endpoints (100 req/s)
- **Admin login**: Protected by rate limiting and strong password requirements

## Secret Management

### Environment Variables

All secrets are injected via environment variables — never hardcoded in source code.

### Key Rotation

```bash
# Generate new JWT secret
python scripts/generate_secrets.py --write-env

# Rotate webhook secrets
# Delete old webhook, create new one (secret is shown once)
```

### .env File

The `.env` file is in `.gitignore` and should never be committed. Use `.env.example` as a template.

## Data Protection

- **Passwords**: Hashed with bcrypt (salt rounds=12)
- **Payment data**: YooKassa handles card data; we only store tokens
- **API keys**: Hashed before storage in the database
- **Telemetry**: No PII is sent to external services except for operational metrics

## TLS/SSL

- All external traffic should use HTTPS (enforced by nginx redirect)
- Self-signed certs are used for development only
- Production uses either Let's Encrypt (certbot) or Cloudflare Tunnel (automatic TLS)

## Compliance

- **GDPR**: User data is stored in PostgreSQL; export/delete requests supported via admin panel
- **PCI DSS**: No card data touches our servers (YooKassa handles payments)
- **SOC 2**: Audit logging enabled for all admin actions
