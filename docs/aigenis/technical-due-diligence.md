# Техническое due diligence и интеграция с Aigenis

> Ответы на вопросы CTO покупателя: стек, архитектура, интеграция в терминал,
> безопасность, данные. Основано на техническом Q&A, плане интеграции,
> threat model и data-room. Позиция по данным (скрейпинг BYN) — §5, читать
> обязательно перед любым звонком.

## 2. Архитектура и data pipeline

```
MOEX ISS (публичный) + market-data адаптеры → scraper/pipeline.py → PostgreSQL
                                                    ↓
          scoring/engine.py (Reward/Risk 0–100) → recommendations (диверсификация)
                                                    ↓
          ml/engine.py (walk-forward CV, YTM-регрессия + buy/hold/wait/avoid)
                                                    ↓
          forecast/engine.py (Monte Carlo + CVaR) → portfolio/optimizer.py (Calmar)
                                                    ↓
          FastAPI → React SPA / Telegram-бот / Partner API / Widget
```

- **Пайплайн:** APScheduler каждые 4–6 ч → MOEX ISS REST (пагинация, rate limit
  с backoff) → Pydantic-модели → валидация (9 проверок: свежесть, YTM bounds,
  цена/номинал, купон, статус; critical → не скорится, warning → коэффициент
  0.85) → async SQLAlchemy upsert → история 5 лет.
- **Fallback:** авто-переключение на запасной источник при недоступности
  основного.
- **Модульный монолит:** scraper / scoring / desk / ml / portfolio / api /
  telegram_bot — каждый модуль независимый пакет, при необходимости выносится
  в отдельный сервис без переписывания логики. Масштабирование: stateless API,
  Redis, горизонтальный скейл `--scale api=3`.

## 3. Интеграция с терминалом Aigenis

### Анализ их веб-терминала
- **Стек:** Angular (SPA), Material Design 3, шрифты Montserrat/Onest,
  брендовый цвет `#004b65`, светлая тема.
- **Дизайн-токены** уже извлечены и воспроизведены в
  `frontend/src/aigenis-theme.css` (цвета, радиусы pill 9999px, тир-бейджи S/A/B/C/D).

### Точки интеграции
1. **Карточка облигации:** блок «Аналитика» — Score 0–100, тир, вердикт, разбор по 9 факторам, ML-рекомендация.
2. **Таблица облигаций:** колонка Score с бейджем, сортировка и фильтр по тиру.
3. **Виджет «Топ облигаций»** на главной.
4. **Новый раздел «Премиум-аналитика»** — Desk + ML + портфель (контент под уже продаваемую подписку).

### Способы интеграции
| Вариант | Описание | Срок |
|---|---|---|
| **A. REST API** (рекомендован для MVP) | Bonds Engine — отдельный сервис в их инфраструктуре; Angular ходит через `/api/aigenis/v1` | 1–2 дня |
| **B. iframe-виджет** | Готовый компонент `AigenisBondAnalyzer.tsx` (таблица + карточка + фильтры по валютам + пагинация) встраивается одной строкой | 1 час |
| **C. White-label встройка** | Полная интеграция в кодовую базу Angular, свои CSS-переменные | 2–4 недели (в поддержке) |

### Контракт `/api/aigenis/v1` (B2B)
- **Auth:** Bearer SSO JWT от Aigenis IdP (iss/aud/exp, подпись через JWKS).
  Scopes: `analytics:read`, `portfolio:read`, `alerts:write`. Fail-closed: нет
  токена → 401, нехватка scope → 403.
- **Эндпоинты:** `GET /bonds` (keyset-пагинация по internal_id, limit 1–100),
  `GET /bonds/{id}`, `POST /portfolio-impact`, `POST /alerts` (идемпотентный).
- **Заголовки:** `X-Request-Id`, `X-Data-As-Of`, `X-Model-Version`, `X-Data-Quality`.
- **Ошибки:** 401/403/404 (`not_covered`)/422; rate limit 429 с `Retry-After`.
- **Deprecation:** изменения объявляются заранее, тег `deprecated` в OpenAPI.
- Полное описание генерируется на `/openapi.json`.

### План работ (2 недели до продакшена)
- **Неделя 1:** развернуть API в их контуре → настроить сбор MOEX ISS →
  пересчёт скоринга → верификация 20 облигаций вручную.
- **Неделя 2:** встроить виджет/колонку Score → блок аналитики в карточке →
  цветовая схема → тесты на реальных данных.

## 4. Безопасность

- **Auth:** JWT HS256 (30 мин), bcrypt (12 раундов), refresh-токены с ротацией,
  Google OAuth, fail-closed валидация.
- **Rate limiting:** Redis, тир-зависимый (Free 60 / Pro 120 / Enterprise 300
  req/min; партнёрский выше). Auth-эндпоинты 10 req/s.
- **Вебхуки:** Telegram — secret token заголовок; партнёрские — HMAC-SHA256
  (секрет показывается один раз); YooKassa — IP-фильтр + перепроверка через
  API + full-amount refund check; защита от replay.
- **SSRF:** DNS-резолвинг с пиннингом IP при регистрации, allowlist, IPv6,
  защита от DNS-rebind.
- **Прочее:** CSP, X-Frame-Options DENY, CORS-allowlist, API-ключи SHA-256,
  XFF-spoofing protection (TRUSTED_PROXY), секреты только через env.
- **Threat model интеграции (сводка):**
  - T-001 несанкционированный доступ → SSO JWT + CORS allowlist. Реализовано.
  - T-002 clickjacking iframe → `frame-ancestors` только на домен Aigenis. Планируется.
  - T-003 эксфильтрация данных → rate limit, пагинация-кэп, нет bulk-экспорта, аудит-логи. Реализовано.
  - T-004 инъекция в order flow → аналитика передаёт только `instrument_id`; решения о заявке — в терминале Aigenis. Дизайн.
  - T-005 webhook replay → HMAC + Idempotency-Key. Частично (идемпотентность есть, HMAC в production).
  - T-006 кража токенов → BFF-паттерн, HttpOnly cookie, без localStorage. Документировано.
  - T-007 браузерный скрейпинг в production → `DEPLOYMENT_PROFILE=aigenis` отключает headless (fail-closed). Реализовано.

## 5. Данные: источники и позиция

### Что реально делает пайплайн
| Источник | Что берём | Статус |
|---|---|---|
| **MOEX ISS** (`iss.moex.com`) | RUB-корпоративы (TQCB) + евробонды (TQOB): цены, YTM, купоны, история | Легально: публичный API биржи, без авторизации |
| **invest.aigenis.by** | Белорусский рынок (BYN): листинг, детали, история | **Серая зона: данные самого Aigenis** (браузерная сессия под собственными учётными данными) |
| Модели ML / скоры | Вычисляются локально | Наш IP |

Ключевой факт: **BYN-часть парсится с ресурсов компании, которой мы продаём
движок.** Это первый вопрос на due diligence — ответ должен быть подготовлен.

### Позиция для звонка (коротко)
> «Белорусские данные мы получали через публичный интерфейс invest.aigenis.by
> с собственной учётной записью — это был путь для разработки и демонстрации
> движка, а не коммерческая перепродажа ваших данных. Мы не публикуем ваши
> данные как отдельный продукт и не продаём подписки на ваш контент. В рамках
> сделки BYN-канал безусловно переводится на ваш официальный партнёрский/
> API-доступ — это часть условий передачи.»

### План перехода на официальные каналы (включается в предложение)
| Шаг | Что делаем | Срок |
|---|---|---|
| 1. Партнёрский API/data-feed от Aigenis | Заменяет браузерную сессию в `scraper/sources/aigenis/` | Неделя 1 |
| 2. Лицензируемые фиды для RUB (при необходимости) | Опционально, зависит от стратегии покупателя | Недели 2–4 |
| 3. Удаление браузерного парсера BYN из репозитория | Чистая передача без «серого» кода | Неделя 1–2 |
| 4. Аудит источников в документации | README + docs фиксируют только официальные каналы | Неделя 1 |

Стоимость фидов — расходы покупателя ($50–500/мес для Cbonds-уровня); работа
по интеграции входит в 3 месяца поддержки.

### Что уже снижает риски (покажи это)
- Парсер работает с rate limit и кэшем — не «долбит» источник.
- **Нет перепродажи сырых данных:** API и подписки отдают аналитику (скоры,
  кривые, вердикты), а не дампы.
- MOEX-сегмент без юридических хвостов вообще.
- Весь код передаётся покупателю — полная прозрачность источников.

### Чего НЕ говорить
- «Это открытые данные, всё законно» — для BYN это неправда и легко проверяется.
- «Мы удалим парсер сразу после сделки» — без плана звучит как «потом разберёмся».
- Шутки про «спиздил» — на due diligence не место.

### Что НЕ является обязательством
- Покупатель не получает «гарантию легальности» scraping-кода: в документах
  передачи указывается, что BYN-канал заменяется официальным, парсер удаляется.
- Договор формулируется как продажа IP аналитической платформы, а не «сервиса
  доступа к данным Aigenis».

## 6. Тесты, ML, деплой, производительность

### Тестирование
- **Unit:** скоринг, desk-расчёты, ML-метрики.
- **Integration:** API с тестовой БД (SQLite in-memory).
- **Security:** auth flow, rate limit headers, admin access.
- **Billing:** webhook, refund validation, идемпотентность.
- **Bot:** gating, навигация, Stars-оплата.
- **Load:** Locust (`tests/load/`). Coverage ~80% критического пути.
- Запуск: `pytest tests/ -v`.

### ML
- 30+ признаков из bond_history; **walk-forward CV** (никакого look-ahead).
- GradientBoosting: регрессор YTM (R² 0.6–0.8) + классификатор
  buy/hold/wait/avoid. Артефакты версионируются (`ml/artifacts/`).
- Переобучение раз в 1–2 недели, пайплайн в `ml/engine.py`.

### Деплой
- Сервер: Docker + Compose, 2+ CPU, 4+ GB RAM, 20+ GB диск; внешний IP или
  Cloudflare Tunnel. `cp .env.example .env` → `docker compose up -d` (9 сервисов).
- Обновление: `git pull && docker compose build && docker compose up -d`
  (миграции применяются автоматически).
- On-premise: без внешних зависимостей кроме MOEX ISS — данные на железе покупателя.

### Производительность
| Метрика | Значение |
|---|---|
| API | 200+ RPS на medium-инстансе |
| Бот | 50+ одновременных пользователей |
| Сбор MOEX (1500+ бумаг) | 30–60 сек |
| Пересчёт скоринга | ~5 сек |
| ML inference | ~1 сек на батч из 100 |

Узкие места: rate limit MOEX, ML-обучение (CPU, запускать офлайн),
PostgreSQL при >100k записей истории (решается партиционированием).
