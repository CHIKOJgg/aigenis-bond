# Bonds Engine - Objection Handling Guide

Полный список возражений, которые поднимет покупатель, с подготовленными ответами.
Структура: Возражение -> Корневая причина -> Ответ -> Бридж к следующему шагу.

---

## Цена / Бюджет

### "Дорого"
**Корень:** Не видит ROI или сравнивает с зарплатой разработчика, а не с проектом.
**Ответ:** "Build vs Buy: разработка с нуля стоит $150-180k и 6-9 месяцев.
Покупка за $45k - экономия $130k. Команда из 12 человек не отвлекается от
основного продукта. Если бюджет ограничен - модульный вариант от $10k:
только Desk или только премиум-тир."
**Бридж:** "Давайте я покажу, какой модуль даст максимальный эффект при минимальной цене?"

### "У нас нет бюджета на это"
**Корень:** Не приоритет в текущем квартале.
**Ответ:** "Понимаю. Тогда рассмотрите white-label лицензию с revenue-share -
вы платите только с выручки. Или зафиксируем цену сейчас, а старт через квартал."
**Бридж:** "Когда у вас начинается планирование бюджета на следующий период?"

### "А можно дешевле / скидку?"
**Корень:** Торг или реально ограниченный бюджет.
**Ответ:** "Базовая цена $25k (IP + документация) без поддержки. Со скидкой
могу предложить: вы предоставляете кейс-стади и рекомендательное письмо
через 6 месяцев - скидка 15%."
**Бридж:** "Если готовы к партнёрству - обсудим условия."

## "Сделаем сами"

### "У нас своя разработка"
**Корень:** Гордость / нежелание признать, что внешнее решение лучше.
**Ответ:** "Отлично - у вас сильная команда. Вопрос в приоритетах: пока
команда пишет Desk 6 месяцев, конкуренты запускают MOEX-продукт. Bonds
Engine не заменяет вашу команду - он даёт им готовый фундамент, который
они могут кастомизировать. 300+ тестов, документация - им не придётся
начинать с нуля."
**Бридж:** "Покажите на созвоне, что у вас уже есть - сравним с тем, что
можно получить за неделю."

### "Наш CTO сказал, что напишет сам за месяц"
**Корень:** Недооценка сложности.
**Ответ:** "Уважаю амбиции. Вот что нужно написать для Full Desk: парсер
MOEX ISS с пагинацией и rate limiting, Nelson-Siegel scipy-оптимизацию,
duration/convexity/DV01/KRD, RV z-score, carry с фондированием, REPO с
haircut, 7 stress-сценариев, ML с walk-forward CV, биллинг YooKassa с
refund-защитой + Stars, JWT-auth, rate limiting, partner API + webhooks,
Telegram-бот 40+ команд, React SPA, SEO. Это 44 000 строк кода. Даже
гениальный CTO не напишет это за месяц, работая 24/7."
**Бридж:** "Я с удовольствием покажу код вашему CTO - пусть оценит объём."

### "Нам нужно не всё, а только часть"
**Корень:** Не хочет платить за неиспользуемые модули.
**Ответ:** "Модульный вариант от $10k. Какой модуль критичен? Desk? Скоринг?
Биллинг? Вы покупаете только то, что нужно. Остальное - опционально."
**Бридж:** "Давайте определим MVP модуль для вашего сценария."

## Данные / Юридические риски

### "Скрейпинг - это юридический риск"
**Корень:** Опасение нарушения законов о данных.
**Ответ:** "Полностью согласен - поэтому продукт построен на публичном API
MOEX ISS. Это открытые данные Московской биржи, с официальной документацией,
без логина и пароля. Никакого скрейпинга закрытых страниц.
Для белорусского рынка (BYN) адаптер данных в рамках сделки переводится
на официальный партнёрский канал - договор или API."
**Бридж:** "Могу прислать ссылку на документацию MOEX ISS - убедитесь сами."

### "Данные с MOEX может взять любой"
**Корень:** Не видит ценности в обработке данных.
**Ответ:** "Верно. Но вопрос не в данных - вопрос в 44 000 строк аналитики
на этих данных: скоринг, ML, Desk, биллинг, бот, фронтенд. Это 6-9 месяцев
работы команды. Данные бесплатны - аналитика стоит денег."
**Бридж:** "Сравните: Bloomberg Terminal берёт те же данные и продаёт за $2000/мес."

### "Что если MOEX изменит API?"
**Корень:** Страх зависимости от внешнего источника.
**Ответ:** "MOEX ISS работает с 2012 года, API стабилен. При изменении -
адаптация парсера занимает 1-2 дня. Это учтено в тарифе поддержки.
Плюс есть fallback-источник для автоматического переключения."
**Бридж:** "За 3 месяца поддержки все изменения API мы отработаем."

## Конкуренция / Рынок

### "Почему вы, а не cbonds / finam / другой вендор?"
**Корень:** Сравнивает с известными брендами.
**Ответ:** "Cbonds - это агрегатор данных за $500+/мес. Bonds Engine -
это ваш СОБСТВЕННЫЙ аналитический движок. Вы покупаете IP, а не подписку.
Код ваш, данные ваши, клиенты ваши. И цена - разовая, а не ежемесячная."
**Бридж:** "Хотите сравнить функционал side-by-side?"

### "Рынок слишком маленький"
**Корень:** Не видит достаточного TAM.
**Ответ:** "Рынок облигаций MOEX - 1500+ выпусков. Частных инвесторов на MOEX -
30+ млн счетов. Плюс корпоративные клиенты, которые хотят аналитику эмитентов.
Это растущий рынок: в 2022-2024 объём торгов облигациями вырос в разы."
**Бридж:** "Ваши клиенты уже спрашивают аналитику облигаций - я видел FAQ."

### "У нас другая аудитория / мы не про облигации"
**Корень:** Не видит fit.
**Ответ:** "Облигации - самый быстрорастущий сегмент после акций. Клиенты,
которые торгуют акциями, диверсифицируются в облигации. Лучше дать им
инструмент у себя, чем потерять их при переходе к конкуренту."
**Бридж:** "Какой процент ваших клиентов держит облигации?"

## Технические возражения

### "Не подходит наш стек (не Python)"
**Корень:** Технологическая несовместимость.
**Ответ:** "API-first архитектура: всё общается через REST. Бэкенд на Python,
но ваш фронтенд может быть на чём угодно. Интеграция через API за неделю.
Плюс партнёрский виджет (iframe) - даже API не нужен для старта."
**Бридж:** "Покажу API-документацию - увидите, насколько просто интегрировать."

### "Нужен on-premise, а не облако"
**Корень:** Требования безопасности / регулятора.
**Ответ:** "Docker Compose - деплой на ваш сервер за день. Никаких внешних
зависимостей, кроме MOEX ISS (публичный API). База данных на вашем железе.
Все данные под вашим контролем."
**Бридж:** "Могу помочь с деплоем на ваш контур в рамках поддержки."

### "Нет мобильного приложения"
**Корень:** Хочет нативное приложение.
**Ответ:** "React SPA + PWA - работает как нативное приложение на iOS и Android.
Установка на домашний экран, офлайн-режим, push-уведомления. Для B2C есть
Telegram Mini App - вообще без установки."
**Бридж:** "Покажу, как PWA выглядит на телефоне - не отличите от нативного."

### "Слишком много функций, сложно поддерживать"
**Корень:** Боится операционной нагрузки.
**Ответ:** "Модульная архитектура: каждый модуль - независимый пакет. Можете
использовать только скоринг и Desk, остальное не деплоить. Плюс 3 месяца
поддержки - я помогаю с настройкой и обучаю команду."
**Бридж:** "Давайте определим, какие модули вам реально нужны."

## Процесс / Сделка

### "Нам нужно подумать"
**Корень:** Не готов к решению / нужно согласование.
**Ответ:** "Конечно. Что именно требует обдумать - цена, интеграция, данные?
Я могу подготовить материалы для вашего руководства: one-pager с ROI,
техническую справку, roadmap интеграции."
**Бридж:** "Когда вернуться с уточнениями - через неделю?"

### "Давайте через полгода"
**Корень:** Низкий приоритет.
**Ответ:** "Через полгода ваш конкурент может уже запустить аналитику облигаций.
Сейчас окно: MOEX-запуск, растущий интерес к облигациям. Я могу зафиксировать
цену сейчас, а интеграцию начать когда удобно."
**Бридж:** "Что должно произойти, чтобы приоритет повысился?"

### "Мы хотим эксклюзив"
**Корень:** Хочет конкурентное преимущество.
**Ответ:** "Эксклюзив на рынок РБ возможен в тарифе $65k (IP + full-time
разработчик). Включает приоритетную поддержку и NDA с запретом перепродажи
в регионе."
**Бридж:** "Обсудим условия эксклюзивности под ваш рынок."

### "Код открытый - мы можем просто скопировать"
**Корень:** Пытается получить бесплатно.
**Ответ:** "Код в приватном репозитории. Даже если бы был открыт - 44 000 строк
без контекста, документации и поддержки требуют месяцев на разбор.
Цена включает передачу контекста, а не просто файлы."
**Бридж:** "Покажу репозиторий под NDA - оцените объём."
