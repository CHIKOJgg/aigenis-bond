## 8. Win-win модель переговоров

### Что получает Aigenis

- быстрый Premium/analytics use case без найма отдельной команды;
- возможность начать с ограниченного pilot и остановиться без sunk cost;
- аналитический слой в их пользовательском сценарии, а не отдельный конкурентный кабинет;
- прозрачный data contract и возможность заменить fixtures официальным feed;
- измеримые KPI: открытие карточки, переход к заявке, повторные визиты, использование Premium.

### Что получаю я

- доступ к product owner и техническому discovery;
- согласованный официальный источник данных или sandbox;
- оплачиваемый pilot с понятным acceptance checklist;
- право использовать обезличенный результат как customer story только с письменного согласия.

### Предлагаемые варианты сделки

1. **Discovery sprint, 1–2 недели:** требования, feed mapping, SSO/data contract, прототип интеграции. Фиксированная стоимость.
2. **Pilot, 4–6 недель:** ограниченный набор инструментов, read-only analytics, KPI и приёмка по checklist.
3. **White-label / licence:** production integration, SLA, обновления и согласованный revenue-share или годовая лицензия.

Не начинай разговор с максимальной цены. Сначала согласуй проблему, владельца, данные и критерий успеха; цену привязывай к объёму пилота и ответственности сторон.

## 10. План домена и публикации

Рекомендуемая схема: отдельный нейтральный домен, например `aigenis-analytics-demo.example` или ваш собственный брендовый домен, без слова `aigenis` до письменного разрешения. Для первого показа лучше использовать `demo.<ваш-домен>`.

### Вариант A — быстрый временный URL

```powershell
docker compose -f docker-compose.demo.yml up -d
cloudflared tunnel --url http://127.0.0.1:8080
```

URL `trycloudflare.com` годится только для внутреннего теста и не является хорошим постоянным адресом для письма.

### Вариант B — постоянный домен через Cloudflare Tunnel

1. Зарегистрировать нейтральный домен и добавить его в Cloudflare.
2. Проверить импорт DNS-записей и только затем сменить nameservers; Cloudflare предупреждает, что неверные записи могут сделать домен недоступным.
3. В Cloudflare Zero Trust создать Tunnel.
4. Создать Published application:
   - hostname: `demo.<ваш-домен>`;
   - service: `http://127.0.0.1:8080` или `http://aigenis-demo:80`, если `cloudflared` в той же Docker-сети.
5. Добавить токен в секрет окружения, не коммитить его в `.env` или Git.
6. Запустить tunnel как отдельный сервис compose.
7. Проверить HTTPS, `X-Robots-Tag: noindex, nofollow`, `/health`, demo flow и отсутствие `/api` proxy.
8. Включить Access policy: только приглашённые email/одноразовый PIN до первого созвона.

Cloudflare Tunnel публикует hostname к локальному HTTP-сервису и автоматически связывает маршрут с tunnel DNS-именем; официальная схема описана в [Cloudflare Tunnel routing](https://developers.cloudflare.com/tunnel/routing/) и [Tunnel setup](https://developers.cloudflare.com/tunnel/setup/). DNS-подключение и nameservers — в [Cloudflare DNS get started](https://developers.cloudflare.com/dns/get-started/).

### Рекомендуемые DNS/URL

```text
demo.<ваш-домен>       — fixtures-only demo
api.<ваш-домен>        — не публиковать до auth/rate-limit review
status.<ваш-домен>     — опционально, только health/status
```

Не публиковать Postgres, Redis, Grafana, Prometheus, Admin и основной API без отдельной защиты.

### Приёмка домена перед отправкой

- HTTPS-сертификат валиден в обычном браузере.
- Demo открывается без второго логина.
- На каждой странице видны `Demo · Aigenis Analytics Preview` и disclaimer.
- `robots.txt` запрещает индексацию.
- `/api`, `/billing`, `/admin`, `/webhook` с demo-домена недоступны.
- Основной сценарий проходит на desktop и mobile.
- Демо не отправляет сетевых запросов к API.
- Есть резервная запись экрана на случай сбоя туннеля.
