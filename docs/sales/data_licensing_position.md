# Позиция по источникам данных — подготовка к due diligence

**Статус:** внутренний документ для подготовки к звонку с Aigenis.
Цель — заранее сформулировать честную позицию по происхождению данных,
чтобы ответ на вопрос «откуда данные и законно ли это» был спокойным,
конкретным и с планом, а не импровизацией.

---

## 1. Что реально делает пайплайн (факты)

| Источник | Что берём | Как | Статус |
|---|---|---|---|
| **MOEX ISS** (`iss.moex.com`) | RUB-корпоративы (TQCB) + евробонды (TQOB): цены, YTM, купоны, история | Публичный REST API без авторизации, с пагинацией и кэшем | Легально: публичный API биржи, данные раскрытия |
| **invest.aigenis.by** | Белорусский рынок (BYN): листинг, детали, история | HTTP API + браузерная сессия (Playwright) под собственными учётными данными | **Серая зона: данные того самого Aigenis** |
| Модели ML / скоры | Вычисляются локально из собранных данных | — | Наш IP |

Ключевой факт для честности: **BYN-часть парсится с ресурсов самой
компании, которой мы продаём движок.** Это не скрытая уязвимость, а
основной вопрос, который зададут первым. Ответ должен быть подготовлен.

---

## 2. Позиция для звонка (короткая версия)

> «Белорусские данные мы получали через публичный интерфейс invest.aigenis.by
> с собственной учётной записью — это был путь для разработки и демонстрации
> движка, а не коммерческая перепродажа ваших данных. Мы не публикуем ваши
> данные как отдельный продукт и не продаём подписки на ваш контент.
> В рамках сделки BYN-канал безусловно переводится на ваш официальный
> партнёрский/API-доступ — это часть условий передачи.»

Ключевые принципы ответа:
- **Не оправдываться, а переводить в сделку.** Парсинг был способом
  разработать движок «на реальных данных», а не бизнес-моделью.
- **Ничего не скрывать.** Если Aigenis увидит источники в коде (а они
  увидят — код передаётся целиком), скрытность хуже, чем прямое признание.
- **Данные не перепродаются.** У продукта нет ни одной подписки «на данные
  Aigenis» — продаётся аналитика (скоры, кривые, ML), вычисленная локально.
- **План перехода готов** (см. раздел 4) — «после сделки мы переключаемся
  на официальный канал, вот конкретный план и сроки».

---

## 3. Чего НЕ говорить

- «Это открытые данные, всё законно» — для BYN это неправда и легко
  проверяется.
- «Мы удалим парсер BYN сразу после сделки» — без плана это звучит как
  «потом разберёмся». Нужен конкретный переход.
- «Никто не пострадал» / шутки про «спиздил» — на due diligence не место.

---

## 4. План перехода на официальные каналы (включается в предложение)

| Шаг | Что делаем | Срок |
|---|---|---|
| 1. Партнёрский API / data-feed от Aigenis (или официальный файл раскрытия) | Заменяет браузерную сессию в `scraper/sources/aigenis/` | Неделя 1 |
| 2. Moex + Cbonds/другие лицензируемые фиды для RUB-сегмента (при необходимости) | Опциональное расширение, зависит от стратегии покупателя | Недели 2–4 |
| 3. Удаление кода браузерного парсера BYN из репозитория | Чистая передача: у покупателя не остаётся «серого» кода | Неделя 1–2 |
| 4. Аудит источников в документации | README + docs фиксируют только официальные каналы | Неделя 1 |

Стоимость: лицензии/фиды — расходы покупателя (обычно $50–500/мес для
Cbonds-уровня), работа по интеграции включена в 3 месяца поддержки.

---

## 5. Что уже снижает риски (покажи это)

- Парсер работает с **rate limit и кэшем** — не «долбит» источник.
- **Никакой перепродажи сырых данных**: API и подписки отдают аналитику
  (скоры, кривые, вердикты), а не дампы.
- История и деривативы (кривые, ML-фичи) — наш IP, вычисляются локально.
- У MOEX-сегмента нет юридических хвостов вообще (публичный ISS).
- Весь код передаётся покупателю — полная прозрачность источников.

---

## 6. Запасной сценарий, если вопрос прозвучит жёстко

Формулировка: «Как вы сами смотрите на то, что движок питается данными,
собранными с вашего сайта?»

Ответ: «Справедливый вопрос. Именно поэтому в предложении отдельной
строкой стоит переход BYN-канала на ваш официальный доступ — мы
рассматриваем этот движок как инструмент, который вы заберёте в свою
экосистему и будете питать своими же данными через партнёрский API.
С точки зрения ценности: вы покупаете не парсер, а аналитический слой —
скоринг, Desk, ML, бот — который в вашей инфраструктуре станет работать
на ваших официальных данных с первого дня интеграции.»

---

## 7. Что НЕ является обязательством

- Покупатель не получает от нас «гарантии легальности» scraping-кода —
  в документах передачи указывается, что после сделки BYN-канал заменяется
  официальным (раздел 4) и парсер-код удаляется.
- Договор формулируется как продажа IP аналитической платформы, а не
  «сервиса доступа к данным Aigenis».
